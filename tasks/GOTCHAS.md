# Gotchas & learnings

Shared brain for build agents. **Read this fully before starting any story.**
Append (never delete) a concise entry whenever you hit something non-obvious: a build
quirk, an API surprise, a decision with a reason. Keep entries to 1–3 lines each.
Format: `- [US-xxx] the gotcha, and what to do about it.`

## Seeded from research (before any code)

- [general] pi packages live under the `@earendil-works` npm scope (recently moved from `@mariozechner`). Pin exact versions (`save-exact`). Docs: https://github.com/badlogic/pi-mono — read `packages/ai/README.md` and `packages/agent/README.md` before using; APIs may differ from blog posts.
- [general] Do NOT read or copy code from github.com/Nadreau/goldfish (it references a provisional patent). Implement independently from our PRD only.
- [general] Toolchain on this machine: Bun 1.2.4 (`/opt/homebrew/bin/bun`), Swift 6.0.3, no Xcode project — we use SwiftPM. Node is available but the brain targets Bun.
- [US-001] SwiftPM does not produce .app bundles. `swift build` yields a bare executable; `scripts/build.sh` must assemble `Minne.app/Contents/{MacOS,Resources,Info.plist}` manually (LSUIElement=true in Info.plist). Dev runs can use the bare executable.
- [US-002] The brain's stdout is reserved exclusively for protocol JSON-lines. Any stray `console.log` corrupts the protocol — route ALL logging to stderr from day one.
- [US-002] pi's own `pi-server`/`pi-protocol` (CBOR) packages are experimental — do not use them; we own a thin JSON-lines protocol defined in `brain/src/protocol.ts`.
- [general] Every story must leave the repo green: `swift build` in `app/`, `bun run typecheck` + `bun test` in `brain/`. Never commit red.
- [general] Commit style: one commit per story, message `US-xxx: <summary>`, ending with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`. Do not push — the orchestrator pushes after verification.
- [general] Only touch `tasks/GOTCHAS.md` (append) among the tasks/ files — `progress.md` and the PRD are orchestrator/human-owned.

## Learnings (append below)

- [US-001] `bun add --exact -d typescript` now resolves to TypeScript 7.x (the Go-based compiler); `tsc --noEmit` works fine with it under strict settings. Pinned: typescript 7.0.2, @types/bun 1.3.14.
- [US-001] Swift 6 menu-bar skeleton: `@main @MainActor final class ... : NSObject, NSApplicationDelegate` with a custom `static func main()` that sets `NSApp.setActivationPolicy(.accessory)` (Dock-less for the bare dev executable; the bundle gets LSUIElement from Info.plist).
- [US-001] Locate SwiftPM's output with `swift build -c release --show-bin-path` instead of hardcoding `.build/release` — the path is arch-specific (`.build/arm64-apple-macosx/release`).
- [US-001] `bun build --compile src/main.ts --outfile <path>` produces the single-file brain binary (~57MB, embeds the Bun runtime); it runs standalone with no bun install on the target.
- [US-001] `bun build --compile` leaves stray temp files named `.<hash>-00000000.bun-build` in the cwd; add `*.bun-build` to .gitignore or they end up committed.
- [US-001] Minimal working Info.plist keys for the manual bundle: CFBundleExecutable, CFBundleIdentifier, CFBundleName, CFBundlePackageType=APPL, CFBundleShortVersionString, CFBundleVersion, LSMinimumSystemVersion, LSUIElement, NSPrincipalClass=NSApplication. Validate with `plutil -lint`.
- [US-002] Bun 1.2.4 buffers a *piped* stdin until EOF for `Bun.stdin.stream()`, `for await (of console)`, AND node-style `process.stdin` events — deadlocks any request/response protocol. Read fd 0 with node:fs `read()` instead (`stdinChunks()` in brain/src/jsonlines.ts); regression test "responds while stdin is still open" in main.test.ts.
- [US-002] Swift: never iterate `FileHandle.bytes.lines` from an actor-isolated Task — AsyncBytes runs its blocking read(2) inline on the iterating executor, parking the whole actor (deadlocked under `swift test`, only won the race in the app). Bridge readabilityHandler → AsyncStream instead (see BrainClient.lineStream).
- [US-002] `swift test` CAN test an executable target on macOS: `.testTarget(dependencies: ["Minne"])` + `@testable import Minne` works fine despite `@main`. But `swift test` buffers ALL output until the run ends — a hung async test shows nothing; diagnose with `sample <xctest-pid>`.
- [US-002] `bun run script.ts` spawns a *child* bun process; Swift's `Process` holds the parent. When kill-testing crash restart, kill the parent pid (the one Process reports), and beware orphaned children from killed test runs lingering and matching pgrep patterns.
- [US-002] Swift 6 strict concurrency: a mutable local captured by `readabilityHandler` errors ("captured var in concurrently-executing code"); `nonisolated(unsafe) var` is the fix when the closure is serialized on one dispatch source, and `nonisolated(unsafe)` on FileHandle locals is unnecessary (FileHandle is Sendable in the macOS 15 SDK).
- [US-003] pi-ai 0.84.2 real API: `models.login(providerId, "oauth" | "api_key", interaction)` where interaction = `{signal?, prompt(p), notify(e)}`; prompt types text/secret/select/manual_code, notify types info/auth_url/device_code/progress. `models.checkAuth(id)` gives auth state WITHOUT refreshing OAuth (use for status); `models.getAuth(id)` refreshes. Both anthropic OAuth *and* api_key login flows exist on the same provider — api_key login just prompts `secret` via the same interaction.
- [US-003] pi OAuth impls load via bundler-opaque dynamic imports that `bun build --compile` cannot follow — but pi ships the fix: call `registerBunOAuthFlows()` from `@earendil-works/pi-ai/bun-oauth` at startup to register them statically. With that, the real Anthropic OAuth flow (claude.ai authorize URL + localhost callback server) runs fine from the compiled binary. The `.lazy` API wrappers (literal `import()` specifiers) bundle fine without help.
- [US-003] pi CredentialStore contract subtlety: `modify(id, fn)` is the ONLY write path and `fn` returning undefined means "leave unchanged" (not delete — that's `delete()`); Models runs OAuth refresh inside `modify`, so the store must serialize operations (promise chain) or tokens can double-refresh.
- [US-003] `models.login()` can park forever on `interaction.prompt()`; the brain's request loop must dispatch handlers WITHOUT awaiting them (the answering `auth_reply` arrives on the same stdin), and at stdin-EOF pending logins must be aborted or `Promise.allSettled(inFlight)` hangs the exit.
- [US-003] Anthropic's OAuth flow races a localhost callback server against the `manual_code` prompt; when the callback wins, the prompt is cancelled via `AuthPrompt.signal`. An app showing a modal for the prompt should expect it to become stale (the brain answers stale `auth_reply`s with invalid_request — harmless).
- [US-003] Bun.spawn typing under strict TS: don't pass explicit generic params or annotate the reader as DOM `ReadableStreamDefaultReader` (Bun's reader wants `readMany` and a read() arg) — wrap Bun.spawn in a helper and use `ReturnType<typeof helper>`, or a small structural type for the reader.
- [US-003] `bun test` sets no env isolation: subprocess tests touching auth/config MUST set `MINNE_APP_SUPPORT_DIR` (and use `MINNE_MOCK_PROVIDER=1` for the scripted OAuth provider in src/mock-provider.ts) or they'd hit the real `~/Library/Application Support/Minne` and inherit the user's ANTHROPIC_API_KEY.
- [US-004] pi-agent-core 0.84.2 matches its README: `new Agent({initialState:{systemPrompt, model}, streamFn: models.streamSimple.bind(models)})`, `subscribe()` for `message_update`/`text_delta`, `await agent.prompt(text)`, `agent.abort()`. Pin the same version as pi-ai (0.84.2) — they share types.
- [US-004] StreamFn contract surprise: provider failures do NOT reject `agent.prompt()`. They arrive as a final assistant message with stopReason "error"/"aborted" + `errorMessage`, and the Agent PUSHES that failed message into `state.messages`. Inspect the last message after prompt() resolves, and roll errored exchanges out of the transcript yourself or the next turn replays them to the LLM.
- [US-004] Deterministic no-network streaming for tests: `createProvider` accepts a hand-written `api: ProviderStreams` (`{stream, streamSimple}` returning `createAssistantMessageEventStream()`); pushing a terminal `done`/`error` event completes the stream — no `end()` call needed. See mock-provider.ts.
- [US-004] `agent.abort()` reaches the stream function as `options.signal`; a custom stream must watch it and emit `{type:"error", reason:"aborted"}` with the partial message. Protocol decision: an aborted *chat* terminates with `done {aborted:true}` (partial text is valid content); an aborted *login* keeps error code "aborted".
- [US-004] Both main.test.ts and BrainClientTests used `chat` as the canonical "unimplemented" request — without env isolation. The moment chat went live those tests would have made real LLM calls had credentials existed. When bringing a stub to life, grep ALL tests (both languages) for the request type.
- [US-004] Shared subprocess harness now lives in brain/src/test-support.ts (BrainSession, hello); bun test only collects `*.test.ts`/`*.spec.ts`, so helper modules under src/ are safe to import from tests.
- [US-005] `peekaboo menubar click` opens a status-item menu but it closes the moment the peekaboo process exits — you can never screenshot it from a follow-up command. Working recipe: background `osascript` doing `click menu bar item 1 of menu bar 1 of process "Minne"` (menu bar 1, not 2 — LSUIElement apps have no regular menu bar), `sleep`, `screencapture -x`, then key code 53 to dismiss.
- [US-005] SMAppService.mainApp only works from a real .app bundle; the bare SwiftPM dev executable has no bundle identity, so gate the Launch at Login menu item on `Bundle.main.bundleURL.pathExtension == "app"` and disable it in dev runs.
- [US-006] `AXIsProcessTrusted()` reports **true** for a binary launched from a terminal that itself has Accessibility (Ghostty/iTerm): TCC attributes the child to the responsible parent process. Always verify permission behaviour with `open -a build/Minne.app`, never by running the bundle's binary from the shell.
- [US-006] Swift 6 rejects `kAXTrustedCheckOptionPrompt` ("reference to var … is not concurrency-safe") because it imports as a mutable global. Use the literal key string `"AXTrustedCheckOptionPrompt"` in the `AXIsProcessTrustedWithOptions` dictionary.
- [US-006] Calling `AXIsProcessTrustedWithOptions(prompt: true)` is what adds Minne to the Accessibility list; the `x-apple.systempreferences:…Privacy_Accessibility` deep link alone opens a pane with no Minne row to flip. Do both, prompt first.
- [US-006] There is no notification for a TCC grant — poll `AXIsProcessTrusted()` (1s while onboarding is visible, 5s in the background) and also poll on `applicationDidBecomeActive`, which is when the user returns from System Settings.
- [US-006] TCC cannot be revoked programmatically, so the degraded no-capture path is unreachable on a granted Mac. `defaults write sh.minne.app simulateNoAccessibility -bool YES` forces `CapturePermissionState.missing` (fails closed); flipping it back mid-run is also how the live auto-advance was verified.
- [US-006] `swift format` defaults to 2-space indentation and reflows unrelated lines — the repo is 4-space/100-col. Run it with `--configuration` `{"version":1,"lineLength":100,"indentation":{"spaces":4}}` and check `git diff --stat` for files you never touched.
- [US-006] `peekaboo click "<label>" --app Minne` intermittently fails to find AppKit buttons ("increase --wait-for timeout"); `osascript -e 'tell application "System Events" to tell process "Minne" to click button "X" of window 1'` is reliable for driving windows, as is `click menu item N of menu 1 of menu bar item 1 of menu bar 1` for the status menu.
- [US-007] `AXObserverCallback` is a C function pointer, so it cannot capture: pass the instance as the refcon (`Unmanaged.passUnretained(self).toOpaque()`), add `AXObserverGetRunLoopSource` to `CFRunLoopGetMain()` with `.commonModes`, and re-enter with `MainActor.assumeIsolated` — the callback really does arrive on the main thread.
- [US-007] `kAXFocusedWindowChangedNotification` is posted on the *application* element but `kAXTitleChangedNotification` is posted on the *window* element. Register the title notification on the focused window and re-register it every time focus moves, or window-title tracking silently never fires.
- [US-007] AX attribute reads are synchronous IPC into the target app — a hung app would freeze our main thread. Call `AXUIElementSetMessagingTimeout(appElement, 2)` on every app element you create.
- [US-007] AX trees repeat text relentlessly (a container's `AXTitle` is usually its child's `AXValue`); without a `Set` of already-collected strings per snapshot, a small window yields tens of KB of duplicated noise.
- [US-007] Browsers and Finder expose the address as `AXURL` — a CFURL, not a String, and it lives on the web-area/content element deep in the tree, not on the window. Take the first one the walk finds (verified live: Chrome gives `https://…`, Finder gives `file:///…`).
- [US-007] `NSWorkspace.frontmostApplication` will happily hand you Minne itself; skip your own pid or the chat window gets captured into memory and echoes back.
- [US-007] Keep `swift test` AX-free: the tree walk sits behind the `FocusedWindowSource` protocol (only `AccessibilityWindowSource.swift` touches AX) and every scheduling/dedup test drives a scripted fake.
- [US-007] Don't mix a synthetic test clock with `CaptureEngine.start()`, which ticks at the real `Date()`: the per-window debounce then compares a 1970-epoch timestamp against now and skips everything. A test uses either `tick(now:)` on a synthetic timeline or `start()` on the real clock, never both.
- [US-007] Near-duplicate metric is Jaccard over word 3-shingles (`TextSimilarity`), not a token set — a bag of words calls any two windows of the same app identical because they share the UI chrome vocabulary.
- [US-007] A long osascript-driven smoke run dies when the screen locks: `tell application "X" to activate` blocks forever at the login window (and capture starts logging `com.apple.loginwindow`). Keep drive scripts under ~2 min and check `ioreg -n Root -d1 -a | grep CGSSessionScreenIsLocked` — the key is absent when unlocked.
- [US-007] Measured budget: the dev binary averaged 0.1% CPU / 32 MB RSS over 2 min of app switching including 23 KB Finder walks (`ps -o %cpu=,etime=,rss= -p <pid>` gives the lifetime average, which is exactly the "<1% average" criterion).
- [US-008] A greedy regex with optional separators swallows the *next* word or number ("IBAN … 7654 32 please", "card … 1111 123") and then fails its checksum, silently leaking the secret. Don't trust the first match: re-cut it along its separator groups and validate every contiguous sub-span, longest first (`SensitiveMasker.refineByGroups`).
- [US-008] Luhn alone is not enough for cards — spaces between spreadsheet columns glue unrelated numbers into 13–19 digit runs that pass one time in ten. Also requiring a printed card *layout* (one unbroken run, or 3–5 groups of 4–6 digits) cut false positives on a 47 KB page of numbers from 308 to 35.
- [US-008] Masking a full 50 KB snapshot costs ~30 ms on the main thread (five NSRegularExpression rules) — fine at once per 15 s per window. Mask *before* the byte cap: `▮▮▮` is 9 UTF-8 bytes, so masking can grow the text past a cap applied first.
- [US-008] `AXURL` only surfaces during the tree walk, so the domain blacklist can only reject a snapshot after the walk has happened (bundle-id and private-window-title rules run before it). Blacklisted domains therefore cost one discarded walk — no snapshot is ever produced, which is what the story asks.
- [US-008] Chrome ignores every AppleEvent while a "<terminal> wants access to control Google Chrome" TCC prompt is pending — `osascript` just hangs until its 120 s timeout, and the prompt can be hidden behind other windows. Drive Chrome without automation permission instead: `open -na "Google Chrome" --args --incognito <url>` opens a real incognito window, `open -a "Google Chrome" <url>` opens a tab.
